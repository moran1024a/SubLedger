## 前端定位

前端面向个人和小团队的订阅账目管理场景，负责页面展示、交互状态、表单校验、错误提示和用户操作确认。账单生成、统计计算、通知发送、权限校验、Session 生命周期和日志写入由后端负责，前端不复制这些业务规则。

当前前端保留 Vue 3 单页应用结构，不引入 SSR、Axios、额外状态管理、PWA、深色模式或国际化框架。

## 技术栈与命令

- Vue 3.5、TypeScript、Vite 8。
- Vue Router 4、Pinia 3、Element Plus。
- 原生 `fetch`，测试使用 Vitest、Vue Test Utils 和 jsdom。
- Node.js 版本要求为 `>=20.19.0`，依赖由 Corepack 管理的 pnpm 锁定。

在项目根目录执行：

```bash
corepack pnpm --dir frontend install --frozen-lockfile
corepack pnpm --dir frontend dev
corepack pnpm --dir frontend typecheck
corepack pnpm --dir frontend lint
corepack pnpm --dir frontend test:unit
corepack pnpm --dir frontend build
```

开发服务器通过 Vite 代理 `/api` 和 `/health` 到本地后端。前端命令只用于开发、测试和构建；生产运行方式见 [项目安装与部署](../README.md#安装与部署)。

## 前后端职责

前端负责：

- 路由、角色菜单、页面布局和响应式展示。
- 表单输入、前置校验、加载/空/错误状态和操作确认。
- 将 API 字段错误显示到对应表单，并显示 Request ID。
- 按当前用户币种、时区和语言格式化已由后端返回的数据。
- 发起登录、账单、通知、日志、资料和管理员操作请求。

后端负责：

- Cookie Session、角色权限、数据隔离和登录限流。
- 账单周期、实例生成、金额快照、有效性和统计语义。
- 通知发送、敏感配置加密、调度任务、日志持久化和健康检查。

接口冲突时不要以本文件中的摘要覆盖后端实现，直接查阅 [`../backend/README.md`](../backend/README.md)。

## 路由与权限

公共路由包括登录、禁止访问和未找到页面。登录后，普通用户可访问首页、账单规则、账单实例、通知设置、个人资料和个人日志；管理员可访问管理首页、用户管理、用户日志和系统日志。

路由守卫在导航阶段恢复 Cookie Session，并按用户角色限制管理员路由。Session 缺失或过期时清空内存中的用户状态并回到登录页；已认证用户访问登录页时回到应用首页；认证但权限不足时进入禁止访问页。

管理员身份同时要求后端返回的 `id === 0` 和 `role === 'admin'`，前端不只依据用户名判断管理员。

## 页面与交互

### 登录

登录表单发送用户名和密码，使用后端统一的凭据错误提示，不区分用户不存在、账户停用和密码错误。请求期间按钮锁定；登录成功后按原目标地址进入应用。

### 普通用户

- 首页展示后端统计摘要、下一笔账单和最近账单。
- 账单规则页支持搜索、周期/状态筛选、新建、查看、编辑、停用、启用和永久删除；删除成功后列表会刷新，详情页会返回规则列表。
- 账单实例页支持分页、日期/规则/状态筛选，以及带确认的无效和恢复有效操作。
- 通知设置页支持邮件、飞书、提前提醒和当日提醒配置，并可测试已保存的通道。
- 个人设置页支持修改用户名、时区、默认货币和密码。
- 个人日志页支持查看日志文件和下载单文件或全部日志。

金额变更、规则排期变更、规则停用、规则删除和账单标无效等会影响历史或未来数据的操作，都必须在提交前明确说明后端副作用。删除确认会说明操作不可恢复，并以账户时区区分边界：今天以前的已过账单保留，今天及未来账单删除且不再提醒。前端不自行生成账单或统计结果。

### 管理员

管理员首页显示账户统计和健康状态。用户管理支持创建、修改、重置密码、停用和启用普通用户；用户详情可进入对应用户日志。系统日志和用户日志页支持查询、重试和下载。

所有写操作和下载操作都有独立的加载状态，避免重复提交；首次加载失败显示可重试的错误状态，而不是伪装成空列表。通知配置成功加载前禁止保存，加载失败后通过重试恢复。

## 布局与响应式

桌面端使用侧栏和顶部栏，移动端使用抽屉式导航。品牌以“订阅本”为主标识，以 `SubLedger` 为副标识。菜单活动状态按完整路径匹配，`/admin` 不会在所有管理员子页面同时高亮。

内容卡片中的表格在窄屏下允许横向滚动；页面头部和操作区可换行；表单和对话框适应小屏宽度。交互控件保持单一可聚焦元素，不使用链接包裹按钮的嵌套结构。

## API 客户端

API 基础前缀默认为 `/api/v1`，可通过构建环境变量覆盖。Cookie Session 请求必须使用 `credentials: 'include'`，前端不保存 Session Token、密码、SMTP 密码、飞书 Webhook、账单或日志内容。

客户端统一处理：

- JSON 成功响应、`204 No Content` 和非 JSON 错误。
- `401` 会清空认证状态并由应用入口处理跳转；登录凭据错误留在登录页。
- `403` 进入禁止访问页。
- `422` 的字段错误映射到表单，未知字段保留为表单级错误。
- `500`、网络错误和下载错误显示安全的业务提示及可用的 Request ID。
- 日志下载的文件名从响应头解析，不根据用户输入拼接本地路径。
- 账单日期筛选清空后省略空参数，保留 `false` 和 `0` 等有效值。

敏感通知字段在保存时，空输入应被省略，使后端保留原值；前端不把空字符串当成清除密钥的方式。通知时间在界面使用 `HH:mm`，传给 API 时使用 `HH:mm:ss`。

## 状态管理

Pinia 只保存认证用户、应用 UI 状态和必要的导航状态。认证 Store 负责初始化、登录、退出、清空用户和当前用户信息，不直接依赖 Router；应用入口注册 API 的 401/403 处理器。

账单、统计、通知、日志和管理员列表保持页面级状态，加载、错误、提交和下载状态由对应页面或组件管理。敏感信息不写入 localStorage 或其他持久化存储。

账单查询和管理员用户日志查询仅接受最新请求的结果、错误和加载状态。切换或清空日志用户时立即清除旧列表；新列表加载期间禁止下载。

## 组件与格式

公共组件包括页面头部、加载状态、错误状态、空状态、金额文本、状态标签、确认操作和日志文件表格。表单组件接收字段错误和提交状态，避免各页面重复解析 API 错误结构。

- 金额使用后端返回的字符串，显示时结合当前用户币种。
- 纯日期按 `YYYY-MM-DD` 处理，不经浏览器 UTC 转换。
- 周期显示支持单次、月、季、年和自定义天数；账单实例响应直接携带 `cycle_days`，因此删除规则后仍能显示精确的“每 N 天”。
- 自定义周期限制为 `1` 到 `36500` 的整数天数，输入范围与后端校验一致。
- 服务器错误不显示内部堆栈；字段级错误优先显示在对应输入下方。
- 破坏性操作使用确认框，提交期间禁止重复操作。

## 安全约定

前端只通过同源 Cookie Session 与后端通信，不读取或持久化 Session Token。密码和通知密钥只通过 HTTPS 部署环境中的表单提交，不写入日志、路由参数或浏览器持久化存储。

前端校验用于改善交互，不替代后端权限、Schema 和业务校验。用户可配置的 SMTP/飞书目标由后端处理，生产网络应由部署环境限制不必要的出站访问。

## 测试

测试不启动或下载真实浏览器，使用 Vitest、Vue Test Utils 和 jsdom：

- 单元测试覆盖 API 客户端、账单查询空参数、格式化、周期边界校验、认证和路由守卫。
- 组件测试覆盖登录、账单表单、通知加载和保存保护、账单及用户日志请求乱序、管理员用户、日志下载和布局。
- 受控流程测试覆盖普通用户和管理员的 API 调用顺序、错误语义和关键业务流程。

后端 API、数据库、SMTP、飞书和 Docker 的真实验证不属于前端单元测试门槛，部署验证见 [项目安装与部署](../README.md#安装与部署)。

## 构建产物

`corepack pnpm --dir frontend build` 会先进行 TypeScript 检查，再生成 `frontend/dist/`。生产模式由 FastAPI 托管该目录，并为前端历史路由提供回退；前端不单独维护生产容器或独立 API 服务。部署、端口和首次启动说明见 [项目安装与部署](../README.md#安装与部署)。

## 当前范围

当前前端不包含注册、密码找回、支付记录、汇率、图表、日历、CSV、批量编辑、PWA、深色模式或多语言功能。侧栏状态、账单数据和通知数据不做跨刷新持久化，后端接口不支持的功能不会在前端增加模拟入口。
